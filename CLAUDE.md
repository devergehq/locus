# Locus Project

Locus is a platform-agnostic adapter that sits across AI coding platforms (Claude Code, OpenCode, etc.). It generates platform-specific configuration from its own source of truth.

## Platform File Guardrail (CRITICAL)

When working on the Locus project, **NEVER directly edit platform entry-point files**. These files are generated by Locus and will be overwritten on the next `locus platform add <platform>`:

- `~/.claude/CLAUDE.md` — generated by `crates/locus-adapter-claude/src/config_gen.rs`
- `~/.claude/settings.json` (hooks/permissions) — generated by `crates/locus-adapter-claude/src/config_gen.rs`
- OpenCode equivalents — generated by `crates/locus-adapter-opencode/src/config_gen.rs`

**Instead, edit the Locus source code that generates them.** The generation functions are:
- `generate_claude_md()` in `crates/locus-adapter-claude/src/config_gen.rs` — the CLAUDE.md template
- `update_settings_json()` in `crates/locus-adapter-claude/src/config_gen.rs` — hooks and permissions
- Equivalent functions in `crates/locus-adapter-opencode/src/config_gen.rs` for OpenCode

After editing, the user runs `locus platform add claude-code` (or `opencode`) to regenerate.

## Project Structure

- `crates/locus-cli/` — CLI binary (`locus` command)
- `crates/locus-core/` — shared types, error handling, platform abstraction
- `crates/locus-adapter-claude/` — Claude Code adapter (config generation, hooks, events)
- `crates/locus-adapter-opencode/` — OpenCode adapter
- `crates/locus-index/` — codebase indexing
- `crates/locus-tools/` — tool implementations
- `algorithm/` — Algorithm specification (source of truth, inlined into generated CLAUDE.md)
- `skills/` — skill definitions (copied to `~/.locus/skills/` on install)
- `agents/` — agent definitions and traits.yaml (copied to `~/.locus/agents/` on install)
- `protocols/` — protocol definitions (copied to `~/.locus/protocols/` on install)
- `.claude-plugin/plugin.json` — Claude Code plugin manifest (the plugin install path)
- `hooks/` — plugin hook scripts and `hooks.json`
- `skills/locus-algorithm/SKILL.md` — **generated** from `algorithm/v2.0.md` by
  `scripts/gen-algorithm-skill.sh`; edit the spec, not the skill

## Plugin manifest guardrail

Two fields in `.claude-plugin/plugin.json` fail silently if added, both verified
against claude 2.1.263 and both pinned by tests in `crates/locus-cli/src/bundled.rs`:

- **`agents`** *replaces* the default `./agents/` scan instead of extending it, and
  only accepts `.md` file paths (a directory is rejected as `Invalid input`). Omitting
  it is correct — the default scan picks up all 17 agents with no list to drift.
- **`hooks`** — `hooks/hooks.json` is already loaded automatically. Naming it as well
  loads it twice and the plugin fails with `hook-load-failed`. `claude plugin validate
  --strict` does **not** catch this; only the `system/init` event reports it.
